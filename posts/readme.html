What I keep in a README

Mar 14, 2026 · 3 min read · Kairo

A README is not a manual. It is the shortest path from "what is this?" to "it runs". I write one before I forget why the project exists.

One line that says what it is

If the first sentence needs a second sentence to make sense, keep editing. A clear description helps search results, link previews and your own future memory.

The command that runs it

One copyable block, tested from a clean state. No hidden environment variables, no "you probably need to install this" step.

python3 -m http.server 8000
# open http://localhost:8000

One honest limitation

Saying what a project does not do saves everyone time. It also gives you a clean place to put the thing you might add next.

A README that admits a limitation is more trustworthy than one that pretends to be finished.

Wrap up

What it is, how to run it, what it does not do. Five minutes of writing, months of saved confusion.
